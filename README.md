# osek-control: מערכת שליטה לעוסק מורשה

מערכת פרטית, מתארחת אצלך, שמחזיקה את כל הכספים של העוסק במקום אחד.

## מה היא עושה

| מודול | זרימה |
|---|---|
| **חשבוניות ממייל** | Gmail (avi@vibit.co.il) ← כל 15 דק׳ ← חילוץ טקסט מ-PDF ← סיווג לפי **מספר העוסק** מול **ח.פ. החברה** (מוגדרים בדף ההגדרות) ← Drive לפי חודש ← תור אישור ← `files@webenefit.co.il` |
| **וואטסאפ (VEX 0542144442)** | VEX שולח webhook עם הקובץ ← אותו pipeline |
| **העלאה ידנית** | דשבורד ← אותו pipeline |
| **בנק ONE + מקס + כאל** | `israeli-bank-scrapers` כל בוקר 06:30 ← SQLite ← התאמה אוטומטית לחשבוניות (סכום ±₪1, תאריך ±10 ימים) |
| **הכנסות קארדקום** | ייבוא CSV של דוח מסמכים (V1). API בהמשך |
| **דשבורד** | הכנסות, הוצאות, רווח גס, **תנועות שחסרה להן חשבונית**, תור אישור, לבדיקה |

### כללי סיווג
- ע.מ. של העוסק בלבד ← **עוסק**: נכנס לתור האישור
- ח.פ. של החברה ← **ויביט בע״מ**: תיקייה נפרדת, לא נשלח לרו״ח
- שני המזהים / אף אחד / סריקה בלי טקסט / הצעת מחיר ← **לבדיקה**
- זיהוי עמיד ל: אפס מוביל, מקפים, רווחים, טקסט עברי הפוך מ-PDF
- כפילויות (אותו קובץ פעמיים) נחסמות לפי SHA-256

### מבנה Drive
```
<תיקיית העוסק>/2026-11/2026-11-12_Google_117.pdf
<ליד תיקיית העוסק>/ויביט בע״מ - לא לעוסק/2026-11/...
<ליד תיקיית העוסק>/לבדיקה - עוסק/2026-11/...
```
החברה ו"לבדיקה" נשמרות **מחוץ** לתיקיית העוסק בכוונה: אם תשתף את התיקייה עם רו״ח, הוא לא יראה מסמכים של החברה. אפשר לעקוף עם `DRIVE_COMPANY_FOLDER_ID` / `DRIVE_REVIEW_FOLDER_ID`.

### שליחה לרו״ח
- חשבונית אחת במייל, מ-avi@vibit.co.il, נושא: `חשבונית - עוסק מורשה <שם> <מספר> - <ספק> - <תאריך>`
- **שום דבר לא נשלח בלי לחיצה על "אשר ושלח"** (`REQUIRE_APPROVAL=true`). אפשר לסמן כמה ולשלוח במכה.
- מסמך של החברה או "לבדיקה" לא יכול להישלח (חסום בקוד). קודם משנים סיווג.

## הקמה על שרת (Ubuntu + Caddy קיים)
```bash
# DNS: רשומת A לדומיין → IP השרת. ואז, כ-root:
curl -fsSL https://raw.githubusercontent.com/avileon/osek-control/main/deploy/provision.sh | DOMAIN=osek.atar.co bash
```
הסקריפט: משתמש מערכת `osek`, Node 24 פרטי ב-`/opt/osek/node` (לא נוגע באפליקציות אחרות), systemd `osek.service` על 127.0.0.1:3100, בלוק Caddy עם HTTPS. בסוף מודפסת סיסמת הדשבורד **פעם אחת**.

עדכון: `bash /opt/osek/app/deploy/update.sh`

### אחרי ההתקנה: הכל מהדשבורד ← הגדרות
1. מספר עוסק, ח.פ. החברה, מייל רו״ח, קישור לתיקיית Drive
2. Google: העלאת קובץ ה-OAuth client JSON ← "חבר את Google" (Redirect URI: `https://<domain>/oauth2callback`)
3. מקס / כאל: שם משתמש וסיסמה
כל ההגדרות נשמרות מוצפנות AES-256-GCM ב-DB, לא בקוד ולא ב-Git.

### בנק ONE
אין סיסמת בנק במערכת. ייבוא קובץ תנועות ידני, ובהמשך הקונקטור הרשמי של ONE (OAuth, קריאה בלבד) כשיהיה זמין.

## אבטחה
- שרת ייעודי, לא משותף עם פרויקטים אחרים
- `/etc/osek/osek.env` (root:osek 640). הגדרות וסיסמאות מוצפנות AES-256-GCM ב-DB
- דשבורד: Basic Auth מאחורי HTTPS (Caddy). מומלץ להוסיף Cloudflare Access / הגבלת IP
- הסקרייפרים נכנסים לבנק עם הפרטים שלך. כך עובדים כל הכלים מהסוג הזה (moneyman, Caspion). זה לא open banking רשמי
